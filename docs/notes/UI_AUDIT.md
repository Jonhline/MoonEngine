# UI 1:1 audit (18 October 2026)

What the disc's menu projects use that the engine never handles by name. Generated by
`tools/ui_audit.py` from the 33 projects under `/projects/` (215 screens, 44 widget classes, 427
class/property pairs, 1042 engine names reached by the scripts), extracted from the user's own disc:

```sh
python tools/ui_audit.py extracted/ui_audit extracted/ui_audit_report.md
```

The full tables stay local (`extracted/ui_audit_report.md`). Each item names the **original function
that reads it** (the string's lui/addiu reference in `extracted/core.bin`), which is where its proof
starts.

**What this proves and what it does not.** A name that appears nowhere in `src/` as a string is not
read by name: native code reads widget properties with `mp_prop(..., "literal")`, so a property
missing here is ignored when the screen is drawn. Scripts may still store and read an attribute
generically, so a missing name is a candidate, not a certain defect. The reverse is also true: a name
that is present is not proved correct. This is a static lower bound; the dynamic tour below is the
next step.

Out of scope (FIDELITY 4.4, grade N) and left out of the lists: `network`, `online`, `message`
(online messenger), `eyetoy`, `print`, `event` (the LAN battle setup), and natives of the network,
HTTP, XML, printer and EyeToy modules even when an in-scope script reaches them in a LAN branch.

## Directional navigation verification

RootWindow clip angle, front origin and wrap default/override now reach the
native comparator verified against 0026F2B8 and the original rational atan.
Forty thousand pair comparisons, projections and clip-stack intersections pass.
The 0026F9E0 hierarchical collector also matches 2,000 generated widget trees:
visibility, insensitive/focusable flags, nested clipping, empty intersections,
nearest navigation-box priority and all four directions. Its oracle substitutes
widget getters only; the original recursion, projection and clip stack execute.
Authored quick-menu wrap and Options no-wrap checks and their negatives pass.
Original allocation-address ties remain represented by native collection order;
this does not prove overlapping, otherwise identical widgets select identically.
The class-specific getter/default audit and visual PCSX2 tour remain open.

## Dynamic discovery coverage (18 October 2026)

The developer-only headless runner now opens arbitrary project/root pairs,
records VM diagnostics and active-root redirections, and saves requested-tree
captures locally. The corrected report is extracted/ui_tour_native/report.md:
172 roots, 172 captures, 84 roots with diagnostics, three initialization
redirections, no process failures. Positive and WILL_FAIL tests cover diagnostic
retention and rejection of unknown roots. No launcher or first-run UI is used.

This is not a full route/visual pass: caller-dependent arguments and the full
3D/movie presenters are absent. Reproduce warnings through their authored
routes before treating them as defects. PCSX2 comparisons, grid/Logger packing,
TextFace justification, model lighting and the remaining native/list methods
are still open. The watched-car caption, steering HUD and saved display flags
are now covered by the focused tests described above; secondary HUD text and
camera suppression remain open.

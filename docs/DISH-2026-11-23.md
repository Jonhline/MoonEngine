## R1 — Download music (settings → custom music → popup)

**Where:** Settings, row directly under the "Custom music" toggle (`VS_CUSTOM_MUSIC`, `video_settings.c:456`).
**What:** a new row **"Download music"** → popup with:
1. a URL field (clone the save-name text input shape, `save_ui.c:216 SDL_StartTextInput`), song or playlist;
2. Enter starts the job;
3. the popup becomes a scrolling log: per track `name ✓ 12.4 MB` or `✗ <yt-dlp's own stderr line>`;
4. Close. Closing while a job runs is allowed; the job continues and the log reattaches on reopen.

**Tool:** `yt-dlp.exe`, NOT baked in. Create `tools/` in the user folder (`plat_pref_dir`) plus
`tools/manifest.json` = `{name, version, sha256, size}` per managed tool.
- First press fetches yt-dlp into `tools/` with a **byte progress bar** in the popup
  (`tools: fetching yt-dlp 22.5 MB 41%`), pinned to a version + sha256 recorded in the source.
- That same press is the integrity check: missing / wrong size / wrong sha256 → refetch. `mods/` excluded.
- **Never on launch. Never a boot gate.** A background stat at launch is allowed; a bar may only show
  while something is actually downloading.

**Command shape:** playlist → `--paths <Music>/<playlist name>`; single song → `--paths <Music>/`.
Format `-f bestaudio[ext=m4a]/bestaudio`, no transcoder (jukebox reads m4a; libav is in-process).
**Report the real outcome:** filename, duration, and the jukebox's own `added=N` line. Never a lying spinner.
Surface yt-dlp's stderr; a bad URL must produce a readable error.
**Android:** cannot exec a bundled binary → row hidden, one log line saying why. Honest limit.
**GATE:** a pasted URL yields a playable entry in GT Mode → Jukebox with `added=N` in the log; a bad URL
yields a readable error. Screenshot of the popup mid-download + after.

## R1d — a playlist URL is REFUSED: the validator rejects '&'

Measured at HEAD 29ac6cd on the real path: typed
`https://www.youtube.com/watch?v=BaW_jenozKc&list=PLabcdefghijk` and pressed Enter. The popup printed
**`yt-dlp error: URL contains an unsupported shell character`** and never ran the tool.

That character is `&`, which is in **every playlist URL** (`watch?v=…&list=…`) and in most YouTube links with
any parameter at all. Since R1b the spawn is already argv-safe (`posix_spawnp` / `CreateProcessA` with
`CREATE_NO_WINDOW`), so a shell metacharacter list is not the right model: the URL is never parsed by a shell.

**Fix:** validate the URL for what actually matters — length, and no control characters (bytes < 0x20, plus
`\n`/`\r`/`\t`), and it must begin with `http://` or `https://`. Everything else printable is legal, `&`, `?`,
`=`, `%`, `+`, `#`, `:` included. Do not whitelist "shell-safe" characters; there is no shell.
**GATE:** the URL above reaches yt-dlp — the log shows either `[youtube] Extracting URL` (or a real yt-dlp
verdict such as "video unavailable"), never `unsupported shell character`. Also show that a genuinely bad input
(blank, or `notaurl`) still gets a readable refusal.
**Do not touch:** the spawn code, the tool fetch/verify, or the rest of `music_download.inc`.
